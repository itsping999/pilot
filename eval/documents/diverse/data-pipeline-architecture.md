# 数据管道架构设计

## 概述

数据管道是将数据从源系统提取、转换并加载到目标系统的自动化流程。高效的数据管道是数据驱动决策的基础设施。

## 批处理管道

### ETL vs ELT
- ETL（Extract-Transform-Load）：在加载前完成数据转换，适合传统数据仓库
- ELT（Extract-Load-Transform）：先加载原始数据，再按需转换，适合数据湖架构
- 选择依据：数据量、延迟要求、目标存储能力

### 调度编排
- 工具选择：Apache Airflow、Prefect、Dagster
- DAG 设计：按数据域划分，避免单一大 DAG
- 依赖管理：明确上下游依赖，避免循环依赖
- 重试策略：指数退避，最大重试 3 次
- 超时控制：单任务超时 2 小时，DAG 超时 6 小时

### 数据质量
- 格式校验：Schema 验证、类型检查
- 完整性检查：空值率、唯一性、参照完整性
- 时效性监控：数据到达时间、处理延迟
- 异常检测：统计分布偏移、离群值检测

## 流处理管道

### 架构选择
- Apache Kafka：分布式消息队列，适合事件流
- Apache Flink：有状态流处理，支持精确一次语义
- Apache Spark Structured Streaming：微批处理，与 Spark 生态集成

### 处理模式
- 事件驱动：实时响应每个事件
- 窗口聚合：按时间窗口聚合（滚动窗口、滑动窗口、会话窗口）
- CEP（复杂事件处理）：检测事件模式序列
- 变更数据捕获（CDC）：实时捕获数据库变更

### 状态管理
- 状态后端：RocksDB（大状态）、HeapStateBackend（小状态）
- 检查点：定期保存处理状态，支持故障恢复
- 状态 TTL：自动清理过期状态数据
- 水印（Watermark）：处理乱序事件

## 数据湖架构

### 分层设计
- **原始层（Raw）**：原始数据，不做任何处理
- **清洗层（Cleansed）**：去重、格式标准化、空值处理
- **整合层（Integrated）**：跨源数据关联、维度建模
- **应用层（Curated）**：面向业务主题的数据集市

### 存储格式
- Apache Parquet：列式存储，压缩比高，查询性能好
- Apache ORC：Hive 生态首选，支持 ACID 事务
- Delta Lake：支持版本控制、ACID 事务、Schema 演进
- Apache Iceberg：跨引擎表格式，支持时间旅行

### 元数据管理
- 数据目录：统一管理数据资产元数据
- 数据血缘：追踪数据来源和转换过程
- 数据分类：按敏感级别、业务域、数据主题分类
- 数据发现：支持关键词搜索、标签筛选、热门排行
