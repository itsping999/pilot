# 数据库索引策略指南

## 索引基础

数据库索引是提升查询性能的核心技术。合理的索引设计可以将查询时间从秒级降低到毫秒级，而不当的索引则会导致写入性能下降和存储空间浪费。

## B-Tree 索引

B-Tree 是最常用的索引类型，适用于等值查询和范围查询。

适用场景：
- `WHERE column = value` 等值查询
- `WHERE column BETWEEN start AND end` 范围查询
- `ORDER BY column` 排序操作
- `JOIN` 连接条件

复合索引设计原则：
- 遵循最左前缀原则
- 将选择性高的列放在前面
- 考虑查询频率和排序需求
- 索引列数不超过 5 个

## 哈希索引

哈希索引仅适用于等值查询，不支持范围查询。

适用场景：
- 缓存键值对查询
- 精确匹配的高并发查询
- 内存数据库的主键索引

## 全文索引

全文索引用于文本搜索，支持模糊匹配和相关性排序。

实现方式：
- MySQL：FULLTEXT 索引
- PostgreSQL：GIN 索引 + tsvector
- Elasticsearch：倒排索引

## 索引维护

### 索引碎片化
- 定期执行 `REINDEX` 或 `OPTIMIZE TABLE`
- 监控索引碎片率，超过 30% 时重建
- 在业务低峰期执行索引维护

### 索引监控
- 使用 `EXPLAIN ANALYZE` 分析查询计划
- 监控慢查询日志，识别缺失索引
- 定期审查未使用的索引，删除冗余索引
- 统计索引大小，控制存储成本

## 分区表索引

大型表（超过 1 亿行）建议使用分区表：
- 按时间范围分区，便于数据生命周期管理
- 分区裁剪可显著提升查询性能
- 每个分区独立维护索引，降低维护成本

## NoSQL 索引

### MongoDB
- 复合索引遵循 ESR 原则（Equality, Sort, Range）
- 使用覆盖查询避免回表
- 避免过多索引影响写入性能

### Redis
- RediSearch 模块支持全文索引和地理空间索引
- 使用 Sorted Set 实现范围查询
- 合理设置过期策略，避免内存溢出
