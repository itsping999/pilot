### 测试1：Pod是什么？

#### Extractive模式（Ollama嵌入）
```
- 边车容器是与主应用容器在同一个Pod中运行的辅助容器
- Kubernetes将边车容器作为Init容器的一个特例来实现
- Pod启动后，边车容器仍保持运行状态
```

**评分**：⭐⭐⭐⭐☆（4/5）
- ✅ 提到了Pod概念
- ❌ 只是文档片段堆砌
- ❌ 缺乏结构化

#### Generative模式（LLM生成）
```
- Pod是Kubernetes中的最小可运行单元，包含一个或多个容器
- 容器是执行应用程序代码的独立进程
- Kubernetes通过捕获每个容器的日志来监控正在运行的Pod

### 跟踪日志
- 使用kubectl logs命令可以获取Pod的日志信息
- 可以使用--previous参数从先前的容器实例中检索日志
- 在集群级别，日志需要独立于节点、Pod或容器进行存储和管理
```

### 测试2：Deployment和ReplicaSet区别

#### Extractive模式
```
- Deployment对象和一个关联的ReplicaSet对象
- kubectl get deployments hello-world
- kubectl describe deployments hello-world
- kubectl get replicasets
- kubectl describe replicasets
```

**评分**：⭐⭐⭐☆☆（3/5）
- ✅ 提到了两者关联
- ❌ 缺乏解释性内容
- ❌ 只是命令列表

#### Generative模式
```
Deployment和ReplicaSet是Kubernetes中用于管理应用实例的重要概念。
它们的主要区别在于：

1. 生命周期：
   - Deployment通常用于描述一个完整的应用程序部署，包括多个副本
   - ReplicaSet则是为了解决在生产环境中如何保持特定数量的实例稳定运行

2. 行为：
   - Deployment是一种控制器对象，负责管理应用的生命周期
   - ReplicaSet本质上是一个状态机，用于确保应用实例的数量保持不变

3. 使用场景：
   - 在开发阶段或测试阶段，通常使用Deployment
   - 在生产环境，为了保证应用的稳定性和可靠性，会使用ReplicaSet

4. 资源管理：
   - Deployment通过自动扩缩和回滚机制来管理资源
   - ReplicaSet则是手动配置的，需要在生产环境中进行维护操作

5. 扩展性：
   - Deployment支持自动扩缩，可以动态调整实例数量
   - ReplicaSet通常用于手动控制实例的数量
```

## 🎯 技术实现

### 配置参数
```bash
# 嵌入配置
EMBEDDING_PROVIDER=ollama
EMBEDDING_MODEL=qwen3-embedding:0.6b

# LLM配置
LLM_PROVIDER=custom
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_MODEL=qwen2.5:1.5b

# 服务配置
DB_PATH=./data/knowledge-pilot-ollama.db
ADDR=127.0.0.1:8084
```

### 服务架构
```
用户查询
  ↓
Ollama嵌入服务（qwen3-embedding:0.6b）
  ↓
向量检索（SQLite + 余弦相似度）
  ↓
上下文组装
  ↓
Ollama聊天服务（qwen2.5:1.5b）
  ↓
生成式答案
  ↓
返回用户
```

- **内存占用**：150MB（可接受）
